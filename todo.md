# Sandboxing alignment checklist — Pi

Implemented and verified on 2026-11-03 against the Codex, Claude Code, and Antigravity execution boundaries through `align-container-execution-and-sandboxing`. The checked items below retain the original acceptance scope. See [validation evidence](docs/validation.md) for commands, results, and limitations.

## Engine and delegated authority

- [x] **Require a verified Linux rootless launch engine without an override.** Replace the rootless-only query with verification of `Host.Security.Rootless`, `Host.OS`, and `Host.ServiceIsRemote`. Remove the `PI_ALLOW_ROOTFUL` bypass, which currently also activates for `0`. Reject named connections, implicit remote contexts, TCP/SSH endpoints, and Unix endpoints without a pathname beyond slash characters. Support local Podman and explicit same-host absolute Unix endpoints. Perform verification before image operations. Reference: all three baseline launchers.
- [x] **Preserve and validate complete engine responses.** Capture query output without stripping additional trailing records; preserve query failures. Reject incomplete/extra fields, unexpected booleans, additional blank/nonblank records, and CR characters. Apply equivalent validation to launch-engine and delegated-socket queries. Reference: the response capture and validation in the baseline launchers.
- [x] **Enable delegation only for exact `PI_ENABLE_PODMAN=1`.** Other values, including `0`, `false`, `true`, and `yes`, must leave delegation disabled. Apply the same decision to `INSTALL_PODMAN` if client installation remains conditional. When explicitly enabled, fail before build/start if verification fails instead of warning and silently continuing without delegation. Keep Bun installation and native Pi permissions independent. Reference: exact opt-in behavior in all three baseline launchers.
- [x] **Implement verified socket selection and host-side remapping.** Add an absolute socket override, then use an explicit Unix `CONTAINER_HOST`, then `${XDG_RUNTIME_DIR:-/run/user/<uid>}/podman/podman.sock`. Canonicalize the accessible socket, require socket/read/write access, query that exact endpoint, and require rootless `true` plus an absolute reported `Host.RemoteSocket.Path`. Bind the reported host-side path and set the session connection to its container destination. With delegation disabled, omit the mount and explicitly unset session `CONTAINER_HOST`, including values requested through `PI_ENV_VARS`. Do not start services automatically. Reference: all three baseline launchers.

## Identity, state, and mounts

- [x] **Run the agent with the caller's numeric identity in keep-id mode.** Add `--userns=keep-id` and explicit caller UID/GID instead of running Pi as namespace root. Adapt image/home/cache ownership so normal Pi operation, npm extension installation, optional Bun, and Git work without the current root-dependent `DAC_OVERRIDE`, `CHOWN`, `SETGID`, and `SETUID` additions. Remove those additions when the non-root workflow is verified; retain `no-new-privileges`, resource limits, and other existing protections. Reference: the explicit non-root identity in all three baseline launchers. Verify actual Pi workflows rather than treating namespace root as a proven agent requirement.
- [x] **Validate private persistent state before image operations.** Create missing writable state privately with a scoped `umask 077`; resolve physical paths and require caller ownership, read/write/traverse access, and no group/other permissions. Apply this to the writable Pi state and writable shared agent directory. Reject invalid directories without silently chmod/chowning them or importing credentials. Preserve the optional read-only state mode with appropriate read-access checks. Reference: baseline persistent-state checks; Pi currently creates directories after building and does not validate privacy.
- [x] **Use physical workspace paths and remove automatic SELinux relabeling.** Derive the workspace with `pwd -P`, retain that exact absolute source/destination and working directory, and remove automatic `:Z` from workspace/state binds. Keep the existing sensitive-directory guard as an additional protection. Report SELinux access failures without changing host labels or weakening confinement automatically. Reference: baseline physical binds and unchanged host security policy.
- [x] **Provision every required temporary filesystem explicitly.** Disable automatic read-only tmpfs provisioning and explicitly configure `/tmp`, `/var/tmp`, and `/run` with capacities, `nosuid,nodev`, and deliberate execution/access modes. Retain the separate bounded npm-cache tmpfs and add `nodev` to it. Verify mapped-user access and ephemeral lifetime. Pi may keep `noexec` where supported; capacities and execution flags need not equal another agent's. Reference: explicit temporary mount policy in all three baseline launchers.

## Container and image lifecycle

- [x] **Reserve names atomically with bounded collision handling.** Replace the lowest-free-index check followed by `podman run` with `podman create`, using the highest existing suffix plus one across running and stopped containers. Sanitize names consistently, parse bounded decimal suffixes including `08`, propagate listing/lookup errors, and retry confirmed collisions at most 20 times. Never replace an existing container. Reference: baseline naming and reservation logic.
- [x] **Implement bounded, identity-based session cleanup.** Track a full owned container ID through a private CID record and the local create/attach clients. Forward TERM/INT/HUP, preserve the first interruption status and application exit codes including 125, bound graceful waits/control calls/client reaping, and force owned cleanup when required. Reconcile interrupted creation within a finite budget; report unresolved ownership without deleting by name. Preserve stdin/EOF and allocate TTY only when both stdin and stdout are terminals. Place any supported `PI_RUN_TIMEOUT` option before the image and test its native semantics separately from shutdown budgets. Reference: baseline session lifecycle; `exec podman run` and `--init` alone do not implement it.
- [x] **Distinguish missing images from engine/inspection failures.** Automatically build on image-existence status 1 only; reject other statuses. Make failed staleness-label inspection an actionable failure rather than converting it to an empty hash and rebuilding. Keep the version/build-input hash and Bun-aware rebuild behavior. Reference: baseline image-operation error handling.
- [x] **Add explicit wrapper build, shell, and worktree modes.** Provide equivalents of `--container-build`, `--container-shell`, and `--container-git-worktree`, and side-effect-free wrapper help. Worktree mode must expose only the immediate physical parent on explicit request while retaining the original workdir. Apply the same engine/state/socket checks to all session modes and keep wrapper arguments out of native Pi argv. Preserve native Pi `--help` and the existing wrapper-help alias. Reference: shared baseline wrapper modes.

## Acceptance

For each task, extend the existing synthetic wrapper tests and add credential-free real-rootless checks for the changed behavior. Cover failed preflights before builds, exact delegation values and remapped sockets, private state, identity/ownership, temporary mounts, concurrent reservation, redirected stdin, exit 125, signals, stalled creation, and owned cleanup. Reuse disposable native Linux state for permission checks. Update README, SECURITY.md, help, CONTRIBUTING.md, and tests that currently expect the conflicting behavior.

The existing resource limits, network option, read-only configuration option, by-name credential forwarding, default-deny build context, optional Bun, and npm cache are already useful or agent-specific behavior; retain them. The baseline review passed 21 wrapper tests that included conflicting policies. The implementation replaces those expectations, adds protocol/lifecycle regressions, and passes 10 credential-free real-rootless acceptance tests including image builds and optional Bun. Authenticated Pi operations remain unperformed; synthetic engine stalls are distinguished from real runtime checks in the validation evidence.
